# GitHub Pages 公开主页

网址由你的 GitHub 用户名和网页仓库名称决定，发布成功后会显示。

源码仓库与生成网页仓库分开管理。

## 日常使用

1. 双击「启动日记主页.cmd」，会自动打开网页编辑器 <http://127.0.0.1:3310/studio>；保持启动窗口开启。在网页中修改内容、保存并预览即可。
2. 在工作室的「每日一句」标签页，默认编辑今天的句子，也可以选择其他展示日期或「提前写明天」。编辑后点击「保存每日一句」。私人日记仍在 /diary 页面中登录后编辑，两处的句子会同步。
3. 要更新公开网站时，双击「发布公开主页.cmd」，保持网络可以访问 GitHub。
4. 等窗口提示 GitHub Pages 完成构建后刷新公网网址；GitHub 的缓存可能需要一小段时间更新。

也可以在项目目录执行 `npm run publish:web`。第一次使用需 GitHub CLI 登录；便携版在 `.tools/gh/bin/gh.exe`，可以双击「登录GitHub.cmd」。不要把密码或访问令牌放进项目代码。

### 发布失败时

先双击「检查发布连接.cmd」。它只检查登录账号、GitHub API 和目标仓库，不生成或上传网页。

- **登录凭据不可用**：在日常使用的同一个 Windows 用户下双击「登录GitHub.cmd」授权，再检查连接。浏览器登录和发布程序的授权相互独立。
- 登录窗口出现 **Press Enter to open …** 不是失败，请在命令窗口按回车，再在浏览器输入该次显示的一次性验证码并确认授权，最后等待命令窗口显示授权完成。

如果你自行配置了便携 GitHub CLI，可在本机绑定配置目录。凭据、工具和发布状态始终留在本机，不进入源码或网页仓库。
- **连接超时或中断**：检查网络能否访问 `api.github.com`。浏览器自己的代理不一定适用于命令行；如果使用代理，请按代理软件说明为终端配置 `HTTPS_PROXY`。程序不会擅自更改系统代理。
- **网页已上传，等待 Pages 发布**：上传已完成，需等待 GitHub 构建，不要关闭窗口。

双击发布现在直接运行 Node，使用已存在的 GitHub CLI 配置；连接建立失败最多重试两次。读取请求每次最多 25 秒，上传请求每次最多 60 秒。上传请求超时不会盲目重发，以免请求实际已经完成。

`.publish-state/pages.log` 保留步骤与原始错误；`attempt.json` 记录本次发布状态及实际 Windows 用户、程序和配置目录；`check.json` 记录最近一次连接检查结果。`pages.json` 仍保留最后一次已上传版本，不应把它当作最近一次尝试的结果。日志不记录访问令牌。检查通过后，再双击「发布公开主页.cmd」，等显示“发布成功”。

## Markdown 写作

在工作室选择「博客」→「新增文章」，正文默认使用 Markdown，提供编辑、预览、分屏三种视图。输入时即时预览，无需先保存；预览不会自动保存或发布。旧文章可以继续按段落编辑，也可以点击「改用 Markdown 编辑（保留原有文字）」转换，保存后生效。

支持标题、加粗、列表、引用、链接、表格、任务列表和代码块；暂不渲染原始 HTML 或正文图片。文章封面继续在独立的封面位置上传。正文预览和文章页使用同一套排版样式。保存后仍需运行「发布公开主页.cmd」更新公网。

数学公式支持 `$E=mc^2$` 行内写法；独立公式建议将开头和结尾的 `$$` 各放一行。公式在本机预览和公开文章中使用同一套渲染，字体随网页发布，无需外部公式服务。

## 哪些内容会上传

### 私密照片

摄影板块现已支持按年份浏览相册、批量导入和整本私密，操作方式见 [生活相册](PHOTO_ALBUMS.md)。

在工作室「摄影」中选中或新增照片，勾选「私密照片（仅自己可见）」，点击「保存到网页」，再运行「发布公开主页.cmd」更新公网。取消勾选、保存并重新发布即可恢复公开。原有照片默认公开。

私密照片仍可在本机工作室查看和编辑，图片文件、相册标题和说明不会进入发布文件。同一路径的图片即使重复添加到相册，或用作首页、文章、项目封面，也会从公开页面移除。此设置按图片路径生效，重新上传同一张原图会成为另一张照片，需要单独设置。

工作室的 JSON 备份保留私密标记；备份不是对外分享文件。私密照片保存在本机，换电脑时也要保留原来的图片文件。已发布过的图片改为私密后会在下次成功发布时从当前网站移除，但无法撤回别人保存的副本，也不会清除 GitHub 历史提交或缓存。

- 网页、公开博客、公开摄影、作品、关于页及许可署名。
- **发布时已经到展示日期的句子**，按照北京时间判断。
- 不上传日记正文、日记标题、心情、密码、会话、SQLite 数据库、未到日期的句子或本机备份。
- 网页仓库只包含生成后的静态文件，不包含本机源码和私人数据。
- 公网页面没有「私人空间」和「内容工作室」，直接访问对应路径也不会得到这些页面。

## 每日一句的发布说明

GitHub Pages 不运行日记后端。公开主页会按浏览器中的北京时间选择当天的句子，但只能显示**已经发布**的内容。

例如：10 月 11 日在本机给 10 月 12 日写一句话，11 日发布时不会把这句未来留言上传。需要在 **12 日或之后再发布一次**，它才会出现在公网网站。当前没有配置定时发布；电脑上的保存不会自动同步到 GitHub。

修改或撤回已经公开的句子后，也需要重新发布。由于公开 Git 仓库保留提交历史，撤回页面不能保证抹除历史记录，句子应当只包含愿意公开的内容。

## 本机数据

日记仍在 `.diary-data/`。请继续按 [日记说明](DIARY.md) 备份；GitHub 网页仓库**不是日记备份**。

## 检查和预览

- `npm run export:web`：只生成 `.publish-build/site/out`，不上传。
- `node tests/pages-smoke.mjs`：检查生成的网站，验证子目录链接、图片、手机布局和无私人 API 请求。
- `npm test`：验证句子公开边界及日记保存等功能。

发布脚本在创建或使用仓库前会核对当前 GitHub 账号。已有仓库必须带有本项目的生成标记，否则停止或选择新的仓库名，不会覆盖无关仓库。
