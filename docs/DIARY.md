# 日常留存：个人主页与私人日记

基于 [concorde-blade/personal-homepage-studio](https://github.com/concorde-blade/personal-homepage-studio) 改造，保留原项目的博客、摄影、作品、关于页及本地内容工作室。采用暖白纸张与墨绿色的视觉风格。原项目 LICENSE 和 THIRD_PARTY_NOTICES.md 继续适用（CC BY-NC 4.0，非商业）。

## 本机使用

安装 Node.js 24 LTS。在项目目录执行：

```sh
npm ci
npm run dev
```

双击根目录 `启动日记主页.cmd`，就会启动本机服务并自动打开网页编辑器 http://127.0.0.1:3310/studio 。主页预览为 http://127.0.0.1:3310 。已经启动时会复用同一项目，不会重复占用端口；编辑期间保持原启动窗口开启。

- 首页：展示当天的一句话，日历可以回看历史句子。
- 内容工作室 /studio 的「每日一句」标签页：按展示日期编辑、预览、保存和清空句子，可选择今天、明天或过去的日期。此入口仅在本机开发服务可用，不读取或展示私人日记正文。改动与私人日记页中的句子同步。
- 私人空间 `/diary`：第一次打开设置至少 10 个字符的密码，此后使用密码登录。密码不会预先配置。
- 选中一天，写日记、选择心情，并在下方给下一天留一句话，然后点击「保存这一天」。支持补写和修改历史日记。清空句子并保存会撤回对应的公开句子。
- 日期采用 **Asia/Shanghai（北京时间）**。10 月 10 日留下的话属于 10 月 11 日的公开主页；10 月 10 日的日记依然保存在 10 月 10 日。私人日历同时提供当天收到的话、当天日记、当天写给下一天的话。
- 服务端在日期到来前不会返回未来句子。主页每 30 秒及窗口重新激活时刷新；跨日不需要重新部署。
- 私人日记不会进入首页 HTML、公开接口、公开日历标记或公开统计。主页即使在登录状态下也不读取日记正文。
- 「导出备份」下载包含日记与全部句子的 JSON，仅登录后可用，不包含密码和会话。请自行妥善保管下载文件。
- 页脚「内容工作室」在开发模式下可见，可编辑原模板中的站点名称、博客、摄影及作品。原模板的示例内容仍保留并注明示例，请换成自己的资料。

## Markdown 日记

新日记支持 Markdown 输入与实时预览，可切换「编辑 / 预览 / 分屏」。窄屏分屏会将预览放在输入框下方。预览只显示当前输入，仍需点击「保存这一天」保存。

旧日记保持纯文本显示；可通过「正文格式」选择 Markdown，正文内容不变，仅改变解析方式。支持标题、列表、引用、表格和代码块；正文图片和 HTML 暂不显示。日记正文与格式只存在本机私人数据中，不会随 GitHub Pages 发布。

日记也支持 `$E=mc^2$` 行内公式，以及用独占两行的 `$$` 包围的独立公式。纯文本模式不会解析公式。

## 数据与备份

数据保存在 `.diary-data/diary.sqlite`（SQLite）及相邻的 WAL 文件，而不是浏览器缓存。重启、刷新不会丢失已保存内容。这一目录已加入 `.gitignore`，不要放入 `public` 或提交到公开仓库。

可以通过环境变量 `DIARY_DATA_DIR` 指定持久化目录。完整迁移或备份时，停止服务后复制整个 `.diary-data` 目录，再于新机器恢复该目录；包含密码配置和登录会话。应用内 JSON 导出供查阅或外部备份，当前未提供 JSON 导入界面。

密码使用 scrypt 加盐存储，登录会话通过 HttpOnly / SameSite Cookie 验证，有效期 7 天；退出立即撤销。日记正文在服务器磁盘上不是加密存储，应限制服务器与备份目录的访问权限。忘记密码时，可在服务器本机通过下方命令重置，日记保留，所有旧会话失效：

```sh
node scripts/reset-diary-password.mjs
```

按提示输入新密码。只在自己控制的服务器或电脑上执行。

## GitHub Pages 公开展示

已支持静态公开版本，使用免费 github.io 网址，步骤见 [GitHub Pages 说明](GITHUB_PAGES.md)。日记仍在本机，只导出发布时已到展示日期的句子。

## 完整在线日记部署（可选）

如果还需要在公网网站上登录并写私人日记，则需要 Node.js 24 的长期运行服务以及持久化磁盘。下面说明完整后端的部署；GitHub Pages 公开展示无需执行这些步骤。

1. 部署源码，执行 `npm ci` 和 `npm run build`。
2. 设置服务端环境变量（不要使用 `NEXT_PUBLIC_` 前缀）：

```dotenv
DIARY_DATA_DIR=/var/lib/tomorrow-diary
DIARY_PUBLIC_ORIGIN=https://your-domain.example
DIARY_SETUP_TOKEN=使用密码管理器生成的一次性随机设置码
```

3. `npm start` 默认监听 `127.0.0.1:3310`，在前面配置 HTTPS 反向代理。`DIARY_PUBLIC_ORIGIN` 必须与浏览器地址的源完全一致，不加尾部斜杠。托管平台需要监听外部接口时使用 `npx next start --hostname 0.0.0.0 --port 3310`，并配置平台的 HTTPS 入口。
4. 第一次进入 `/diary`，展开「在服务器上首次使用？」，填入设置码并设置自己的密码。也可以直接迁移已在本机初始化的数据库。
5. 设置完毕可移除 `DIARY_SETUP_TOKEN`，并配置进程管理及持久化目录备份。不要公开开发服务器；原内容工作室只在本机开发模式下可用。

生产内容更新：在本地工作室修改公开博客、摄影等，保存后重新构建与部署；日记和每日句子由数据库动态提供，日常写作无需重新构建。

## 验证

```sh
npm test           # 日期、发布边界、存储、会话、保存冲突及原模板测试
npm run typecheck  # TypeScript
npm run build     # 生产构建
npm run test:e2e   # Chrome 浏览器完整流程，测试服务监听 3311
```

浏览器测试使用本机 Chrome 和 `.diary-test-data/` 下的独立数据库，不写入正式日记。截图输出到 `test-results/`。首次编译可能需要较长时间。
